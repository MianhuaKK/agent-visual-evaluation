# Trace · Agent 可视化测评

一个用于查看 Agent 行为、检查授权边界、追踪问题证据和整理重测计划的中文可视化工作台。

将功能结果、权限行为、记忆使用和执行上下文放在同一界面，帮助回答：Agent 做了什么、是否符合当前要求、证据在哪里，以及下一次应该验证什么。

> 当前版本是纯前端 MVP，使用手工构造的合成演示数据。尚未接入真实 Agent 执行器、Codex 日志或内部记忆。仓库目前提供可视化网页源码，尚未包含可安装的 `SKILL.md` skill 包。

## 快速开始

无需安装 npm 依赖，也无需构建。

```bash
git clone https://github.com/MianhuaKK/agent-visual-evaluation.git
cd agent-visual-evaluation
```

直接用浏览器打开 `index.html` 即可浏览。建议通过本地静态服务器使用，以便获得稳定的浏览器存储行为。如果已安装 Python：

```bash
python -m http.server 8000 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8000>。Windows 下也可以使用 `py -m http.server 8000 --bind 127.0.0.1`。

## 功能

| 页面 / 功能 | 当前支持 |
| --- | --- |
| 测评总览 | 按唯一案例统计通过、失败和待判断结果 |
| 测评集 | 按功能正确性、权限边界、记忆行为、指令遵循、信息边界筛选，支持名称搜索与结果筛选 |
| 问题与归因 | 聚合未通过案例，查看观察事实、可能原因与证据 |
| 案例详情 | 查看预期行为、实际结果、授权依据、工具调用及影响 |
| 上下文分类 | 在功能案例的完整上下文和记忆案例中，按原始需求、指令、记忆、环境、工具调用和结果聚焦查看 |
| 配置与来源 | 查看固定授权快照，编辑下一次测评的允许 / 需确认 / 禁止规则草案 |
| 边界与覆盖 | 展示已覆盖的演示范围，以及尚未验证的场景 |
| 重测对比 | 保存和查看待验证的修复计划；当前尚无真实重测执行或结果对比 |

### 示例场景

- 功能正确性：正确密码登录、错误密码拒绝、退出后的旧会话失效、空输入校验。
- 权限边界：未经确认删除测试、尝试读取项目外凭据、依赖安装授权不明确、发布记录缺失。
- 记忆行为：旧偏好覆盖当前要求、跨项目使用包管理器约定、拒绝把外部文档内容写成用户偏好。
- 指令与信息边界：识别外部文档中的越权指令、检查错误提示是否泄露预置测试密钥。

统一列表包含 **15 个合成案例：8 个通过、5 个失败、2 个待判断**。案例来自不同演示场景，并非同一次真实运行；删除测试文件的重复记录已合并，多维度标签不重复计数。

## 使用流程

1. 在「测评总览」查看结果分布，按维度或状态筛选。
2. 点击「查看现场」，检查用户要求、操作记录和实际影响。
3. 对功能失败案例进入「修复与重测」；记忆失败案例可直接编辑修复建议。
4. 保存建议后，在「重测对比」查看待验证计划。
5. 如需调整下一次测评规则，在「配置与来源」保存授权草案。

可能原因仍是待验证假设。保存计划不会执行命令、修改被测项目或启动 Agent；编辑授权草案不会修改历史快照或实际工具权限。

## 数据与存储

案例和上下文均为源码中的静态演示数据，当前没有后端、账号系统或跨设备同步。

| 浏览器 localStorage 键 | 内容 |
| --- | --- |
| `trace-plans` | 已保存的修复与重测计划 |
| `trace-permissions` | 下一次测评的授权规则草案 |

数据保存在当前浏览器和当前站点来源下。更换端口、浏览器或清除站点数据后，原有计划可能不可见或被清除。

「边界与覆盖」和「重测对比」页面保留了 JSON 导出入口。当前导出内容为原始 8 个功能案例和已保存的重测计划，尚未完整包含统一列表中的权限、记忆案例及授权草案。

## 项目结构

```text
agent-visual-evaluation/
├── index.html           # 页面骨架、样式与脚本入口
├── app.js               # 基础案例、详情、修复计划与导出
├── permissions.js       # 授权快照、权限场景与证据详情
├── unified.js           # 统一案例列表、记忆案例与配置页面
├── context-switches.js  # 上下文分类与时间线筛选
└── README.md
```

使用原生 HTML、CSS 和 JavaScript。脚本依赖全局变量及已有函数，加载顺序为 `app.js` → `permissions.js` → `unified.js` → `context-switches.js`，修改页面时应保持此顺序。

## 当前限制与后续方向

- 尚无真实日志导入、自动执行、自动判分和对照重测。
- 尚未连接真实记忆存储，来源名称和版本仅用于演示。
- 权限判断用于展示证据，不提供实时权限拦截。
- 尚未覆盖真实数据库、第三方 OAuth、生产负载与网络故障测试。
- 后续可补充日志数据格式、执行器适配、完整报告导出及标准 skill 入口。

目前适合用于交互原型演示、测评流程讨论和后续实现参考。
